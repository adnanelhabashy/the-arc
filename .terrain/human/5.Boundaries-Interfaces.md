# Boundaries & Interfaces

This document is the interface inventory: what a consumer can call, where state can come from, and where boundaries must not be crossed. Every surface below is either shipped, documented, or explicitly gated by a version constant — there is no "undocumented complex surface".

---

## 2. SDK (`packages/sdk`)

`createBbSdk` (`packages/sdk/src/core.ts:67`) returns `BbSdkAreas` (`core.ts:45`) — the same server areas the CLI drives, plus a realtime client (`realtime-client.ts`) that reuses the server's `events-appended` hub. Areas mirror the route groups: `threads`, `hosts`, `envs`, `projects`, `plugins`, `settings`, `files`, `terminals`, `system`, plus `realtime` subscription helpers.

## 4. WebSocket Protocol

Two surfaces, both zod-schema'd:

- **Client protocol** (`apps/server/src/ws/client-protocol.ts`) — used by web app/mobile/desktop. Messages: `wsReady` (auth), `events-appended` (paged event deltas with `sequenceIndex`), `resolveAction`, `steer`, `terminate`, thread-subscription setup/teardown.
- **Daemon protocol** (`apps/server/src/ws/daemon-protocol.ts`) — used by enrolled machines. Messages: `daemonCommand` (typed, versioned by `HOST_DAEMON_PROTOCOL_VERSION = 215`), `daemonEvent` (raw host events), tunnel/connection control.

Coalescing: `NotificationHub` (`apps/server/src/ws/hub.ts:422`) buckets `events-appended` pushes on a 10 ms tick and fans out to subscribed sessions; long-poll fallback serves clients that can't hold a socket.

## 5. Host Daemon Protocol (`@bb/host-daemon-contract`)

`HOST_DAEMON_PROTOCOL_VERSION = 215` (`packages/host-daemon-contract/src/protocol.ts:1`). Server→daemon commands: `thread.start`, `turn.submit`, `stop`, `restartProvider`, `environment.provision`, file/git/terminal primitives, plugin host commands. Every command settles with a typed result; a missing connection yields a typed "daemon offline". A version mismatch negotiates capabilities or refuses (ADR-6). Bridge protocol version: `PROVIDER_BRIDGE_PROTOCOL_VERSION = 2` (`packages/provider-bridge-protocol/src/version.ts`).

## 7. Plugin SDK Surface

Public plugin API lives in `packages/plugin-sdk` and is audited by `packages/plugin-api-map/src/surfaces.ts`. The four surfaces a plugin implements:

| Surface | Entry | Docs |
|---------|-------|------|
| App slots | `definePluginApp` (`app-contract.ts:2688`) | plugging `app.slots.*` |
| Server slots | `BbPluginApi` (`backend-contract.ts:2018`) | routes, cron, providers, tools |
| Host slots | `host-contract.ts` | daemon RPC namespace |
| CLI slots | `app.slots.cli.command` | register subcommands |

New public members require an `experimental_` prefix + audit entry (`docs/api_to_audit.md`). The plugin guide (`docs/plugin-guide*.md`) is the only plugin API reference.

## 9. Boundary Rules (Enforcement)

These are the project's hard lines; violating any is a bug, not a style suggestion.

- Server never provisions workspaces; daemon never decides product policy (ADR-5).
- Wire changes bump `HOST_DAEMON_PROTOCOL_VERSION` (AGENTS.md) — never silently reinterpret.
- New end-user features must be reachable through SDK + CLI, documented in `docs/cli-guide-and-skill.md`.
- Packaged apps must never run builtin plugins from another installed app (`docs/plugin-provenance.md`).
- Ship plugin code as `prepare:bundled` output; never hand-copy `dist/`.
- Tests never mock the DB (`createConnection(":memory:")` + `migrate`, per AGENTS.md).
